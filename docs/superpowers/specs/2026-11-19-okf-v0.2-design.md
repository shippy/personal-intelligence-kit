# OKF v0.2 Integration — Design

**Date:** 2026-11-19
**Status:** Approved (design); implementation pending (handed to a Herdr session)
**Spec referenced:** Open Knowledge Format (OKF) v0.2 — https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md
**Builds on:** `_lib/OKF.md`, `_lib/okf.py` (the v0.1 conformance work, since merged)

## Summary

Upgrade the generated `output/` bundle from OKF v0.1 to the **applicable subset of
v0.2**. v0.2's conformance rules are unchanged (parseable frontmatter + non-empty
`type` + reserved-file structure), so the current bundle is already v0.2-conformant;
this work adopts the v0.2 features that genuinely fit machine-generated personal
reports and resolves two latent frontmatter conflicts.

All emission stays funnelled through `_lib/okf.py::write_concept`, so the change is
concentrated in that helper plus a one-line-per-writer update.

## Approved decisions (locked)

- **`sources`** → minimal structured entries (`[{resource: "source:email"}, …]`),
  derived from each writer's existing coarse feed list. No fabricated credibility
  signals. The old flat `sources: ["email"]` string list is replaced.
- **`stale_after`** → per-type horizons (alerts ~7d, reports ~14d, reflections ~30d).
- **`verified`** → helper *supports* a param, but writers leave it absent (honest
  "unverified" trust tier; nothing human-reviews these reports).

## Frontmatter contract to emit

| Field | v0.2 shape | Notes |
|---|---|---|
| `type` | scalar (required) | unchanged |
| `title`, `description`, `tags` | scalar / list | unchanged |
| `generated` | `{by: <actor>, at: <ISO 8601 datetime>}` | **new** — supersedes `timestamp` |
| `timestamp` | scalar date (`YYYY-MM-DD`) | **kept** as v0.1-compat alias for `generated.at`'s date |
| `sources` | `[{resource: "source:<feed>"}, …]` | **restructured** from flat feed list |
| `stale_after` | ISO 8601 datetime instant | **new** — `generated.at + horizon` |
| ~~`status: "final"`~~ | — | **dropped** — invalid under v0.2 enum (`draft\|stable\|deprecated`); absent ⇒ `stable` |

**Actor convention** (`generated.by`):
- Deterministic skills → `process:<skill>` (e.g. `process:session-analyzer`).
- LLM-authored docs → `<skill>/<model>` when the LLM path actually ran (e.g.
  `weekly-reflection/gpt-5.5`), else `process:<skill>`.

**Explicitly skipped** (don't fit generated reports, even in "full" v0.2):
`verified` emission, the `Attested Computation` type + `# Computation` heading +
`executor`/`attester`, per-claim footnote attribution, `sources` credibility
signals (`author`/`usage_count`/`last_modified`), `usage_window`, the `references/`
convention.

## Components

### `_lib/okf.py` (the core change)

Current `render_frontmatter`/`read_frontmatter` handle only scalars and flat string
lists (dependency-free, by design — see the earlier Codex PyYAML fix; **keep it
dependency-free**). v0.2 introduces nested frontmatter (`generated` is a mapping;
`sources` is a list of mappings), so both must become recursive over the subset we
emit, still without PyYAML:

- **`render_frontmatter` → recursive**, emitting flow style for nested values:
  `generated: {by: "…", at: "…"}` and `sources: [{resource: "…"}]`. Scalars stay
  double-quoted and escaped as today.
- **`read_frontmatter` → recursive** flow-subset parser, so tests can assert
  `fm["generated"]["by"]` and `fm["sources"][0]["resource"]`. Extend the existing
  `_split_flow`/`_unquote` machinery to recurse into `{…}` mappings and nested `[…]`.
- **`write_concept` gains:**
  - `generated_by: str` (required) — the actor string.
  - `source_feeds: list[str] | None` — coarse feed names, rendered to
    `sources: [{resource: f"source:{feed}"}]`.
  - `stale_days: int | None` — overrides the per-type default.
  - `verified: list[dict] | None` — accepted and rendered if given; writers pass
    nothing.
  - Computes `generated = {"by": generated_by, "at": <now ISO 8601 datetime>}`,
    `stale_after` = generation instant + horizon, keeps `timestamp` = date.
  - A module-level `DEFAULT_STALE_DAYS = {"alert": 7, "report": 14, "reflection": 30}`
    (reasonable fallback for other types), used when `stale_days` is None.
  - Stops emitting `status`.

Keep `assert_writable`/`out_dir` behaviour exactly as now.

### Writers (one-line-per-writer updates)

The six output writers currently pass `status="final"` and `sources=[…]`. Each must:
drop `status`; pass `generated_by`; rename `sources=` → `source_feeds=`. LLM-capable
writers (weekly-reflection, intention-reality-gaps, stale-drafts) pass the
`<skill>/<model>` actor when their LLM path ran, else `process:<skill>`.

> **Implementer note:** re-read each writer against *current* `main` before editing —
> the writers now route run-logging through an `activity` module (`append_activity`),
> and exact call sites/args have changed since the v0.1 work. The design above is the
> contract; wire it to whatever the current call sites are. Do **not** touch the
> operational `logs/activity/` + `logs/sync.jsonl` logging — it is separate from the
> OKF `output/log.md`.

### Docs

`_lib/OKF.md` → v0.2: new field table (generated/sources/stale_after, status dropped),
actor convention, the explicit skip-list, and `okf_version: "0.2"` in the manifest
guidance.

## Testing

- Extend `_lib/test_okf.py`: recursive render round-trips for the nested shapes
  (`generated` mapping, `sources` list-of-mappings), `stale_after` computation from
  `stale_days`/defaults, `status` no longer emitted, `read_frontmatter` parses nested
  values. **Must stay dependency-free** — runnable as
  `uv run --no-project --with pytest pytest _lib/test_okf.py` (no `--with pyyaml`).
- Each writer's existing OKF conformance test gets one assertion that
  `read_frontmatter(path)["generated"]["by"]` is set and non-empty.

## Non-goals

- No change to the `data/*.db` SQLite layer or the operational activity/sync logs.
- No re-adoption of PyYAML.
- None of the skipped v0.2 families above.
